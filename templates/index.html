Structure

Three layers, one direction

Every Refrakt app has the same shape. The web layer handles HTTP and HTML, the domain holds your types and logic, the data layer talks to the database.

Domain modules import no Wisp, Lustre, Pog or Sqlight: just your types and functions.

web/handlers, views, forms, layouts, middleware
↓↓
domain/pure Gleam types and functions
↑
data/repos with raw SQL, migrations

✓ web → domain, data ✓ data → domain ✗ domain → anything

Principles

Five rules Refrakt holds to

Before anything is added to Refrakt, it has to make a new Gleam developer more productive in their first hour.

  1. Conventions over assembly. One project layout, one routing shape, one way to structure handlers, views, forms and repos.
  2. Generated code is your code. Every file the CLI writes is plain Gleam you can read, change and keep. There is no hidden framework layer.
  3. No magic, no macros. Routing is pattern matching, views are functions, validation is functions.
  4. Built on the ecosystem. Wisp handles HTTP, Lustre renders HTML, Mist serves it, Pog or Sqlight talk to the database.
  5. Boring where boring is good. CRUD, forms, validation, sessions and layouts come first, and they should just work.

CLI

The commands

A code generator and a few dev helpers. Your app never calls the CLI at runtime.

new <name>
A project, with --db postgres or --db sqlite
gen resource
Full CRUD: handler, views, form, domain, repo, migration, test
gen auth
Register, login, logout, sessions and require_auth
gen page
A handler and a GET route
gen island
A Lustre client-side island
gen live
A Lustre server component over WebSocket
gen migration
An empty, numbered SQL migration
migrate · seed
Run pending migrations, run seeds
routes
Print the route table
dev · build
Live reload on change, compile islands to JS
gen deploy
Dockerfile, migrations in production, fly.toml
diff
See which template changes your app is missing

Built on

The Gleam ecosystem, not a replacement for it

If Wisp or Lustre already does it, Refrakt doesn't rebuild it.

  • WispHTTP handlers, middleware, requests and responses
  • LustreHTML views, islands, server components
  • MistHTTP server and WebSocket
  • PogPostgreSQL client
  • SqlightSQLite client
